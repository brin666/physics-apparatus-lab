# 首页预览启动优化 · 2026-10-26

## 改动与资源

默认视频由 600×520 VP9 WebM 转为 480×416、24 fps、H.264 MP4，文件头前置以支持渐进播放。默认 15 段视频合计由 4,659,266 字节降至 1,449,170 字节。原 WebM 保留为浏览器不支持 MP4 或加载失败时的回退。

鼠标停留 70 ms 后准备对应视频，300 ms 后显示小窗；未开启省流量、慢速网络、减少动态效果时才提前准备。播放器采用最多 3 项的最近使用缓存，只有选中项可以播放；关闭暂停、页面离开时释放。小窗立即复用首页已有器材图，实际首帧呈现后再淡入视频。

## 本地测量

同一浏览器、本地 HTTP 服务，禁用浏览器 HTTP 缓存；CDP 模拟 100 ms 延迟、1.5 Mbps 下载。计时从调用打开小窗开始，到 requestVideoFrameCallback 报告首帧；不包含鼠标停留的 300 ms。

| 首次打开 | v0.3.0 | v0.3.1 |
| --- | ---: | ---: |
| 扬声器 | 681 ms | 323 ms |
| 抽水机 | 1,431 ms | 504 ms |

各一次样本，仅证明此环境下的改进，不能代表所有设备或 GitHub Pages 线路。重复打开时已解码画面立即显示，后续动画仍取决于浏览器调度；没有把缓存画面当成新的视频帧来计算以上数据。

## 功能检查

- 15 个 MP4 均可播放；所有检查中缓存不超过 3 项，关闭后播放数为 0。
- 同步连续切换 6 个器材，最终仅选中的继电器播放，未出现旧异步回调覆盖新预览。
- 阻断抽水机 MP4 请求后，WebM 回退正常播放。
- 390×844 触屏布局可点击播放、关闭后暂停且无横向溢出；减少动态效果时显示器材图，不创建视频。
- 同时阻断两种视频后保留器材图与进入按钮，恢复网络并重新打开可正常重试。
- 84 项既有测试通过，Pages 构建成功。新播放器生命周期由实际浏览器验证，不属于现有 Node 测试覆盖。

## 再生成

更新 master WebM 后，安装 FFmpeg 并运行 `node scripts/optimize-preview-clips.mjs`，目视检查后提交 MP4。日常构建和 GitHub Actions 直接使用已提交的素材，不需要 FFmpeg。
